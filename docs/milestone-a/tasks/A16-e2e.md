## Goal
One suite that proves the milestone's acceptance criteria.

## Do
- Playwright specs named after their AC IDs; two-session helpers in `tests/support/`.
- Auth helper following the A03 decision (real Authelia or test identity provider).
- Extend the axe accessibility check (`tests/support/axe.ts`, `tests/e2e/a11-accessibility.spec.ts`, started in A11 for the signed-out screens) to every main authenticated screen, in light and dark themes, at 390 px width. It must include colour contrast, which jsdom unit tests cannot check.
- Replace the A12 UI-only stubs with the real auth helper: `tests/e2e/ac-02-recipe-search`, `ac-03-recipe-versions`, `ac-14-servings-converter` and `ac-18-finnish-recipes` (`.spec.ts`) currently run against `tests/support/fake-recipes-api.ts` (`page.route('/api/**')`, every response parsed with the `packages/contracts` schemas). Rerun the key flows against the real server, including AC-03 version restore and the `409` conflict dialog (R3a: "Open latest version", "Save mine as newest", the second conflict keeping the draft, and a non-409 failure). Use two member sessions for the conflicts. Then delete the fake API and the UI-only labels, or keep a stub only for flows the real server cannot produce.
- Replace the A15 stubs the same way: `tests/e2e/ac-08-shopping-sync.spec.ts` runs against `tests/support/fake-shopping-api.ts` and an init-script `EventSource` stub. Swap both for the real sign-in path against the real server and the real SSE stream, using two member sessions, then rerun AC-08 including the disconnect and reconnect step. Keep the axe checks. Delete the fake shopping API afterwards, or keep a stub only for flows the real server cannot produce.
- Start the real stack from `playwright.config.ts`, so `pnpm e2e` needs no hand-started server:
  - `webServer` starts the API and passes its environment through `webServer.env`.
  - `DATABASE_URL` and `MIGRATION_DATABASE_URL` come from the shared test config (`tests/support/test-database-config.ts`), so E2E uses the same test database and roles as the unit and integration tests.
  - `SESSION_SECRET` and `CSRF_SECRET` are generated fresh on every run in the config (for example `crypto.randomBytes`). No fixed secret values are committed; they live only for the test run.
  - `PUBLIC_ORIGIN` is the Vite test origin. The OIDC settings point at the fake OIDC provider, started as a second `webServer`.
  - Restore the real liveness check (`GET /api/v1/health/live` returns 200) in `tests/e2e/smoke.spec.ts`; the stubbed signed-out redirect check stays.
- Server startup rule: in production the server refuses known test values for the secrets (`SESSION_SECRET`, `CSRF_SECRET`, OIDC client secret), so the test setup cannot leak into a real deployment. Implement it in the platform config validation with a unit test; this is the only server change in this card.
- AC-10 run with AI disabled; run the suite in CI against Compose.

The proper fix is the "Start the real stack" item under "Do", including the startup rule that refuses test secrets in production. The startup rule stays in A16 rather than becoming its own card.
