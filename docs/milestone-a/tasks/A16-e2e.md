Rerun the key flows against the real server, including AC-03 version restore and the `409` conflict dialog (R3a: "Open latest version", "Save mine as newest", the second conflict keeping the draft, and a non-409 failure). - Replace the A15 stubs the same way: `tests/e2e/ac-08-shopping-sync.spec.ts` runs against `tests/support/fake-shopping-api.ts` and an init-script `EventSource` stub. Swap both for the real sign-in path against the real server and the real SSE stream, using two member sessions, then rerun AC-08 including the disconnect and reconnect step. Keep the axe checks. Delete the fake shopping API afterwards, or keep a stub only for flows the real server cannot produce.
- Start the real stack from `playwright.config.ts`, so `pnpm e2e` needs no hand-started server:
  - `webServer` starts the API and passes its environment through `webServer.env`.
  - `DATABASE_URL` and `MIGRATION_DATABASE_URL` come from the shared test config (`tests/support/test-database-config.ts`), so E2E uses the same test database and roles as the unit and integration tests.
  - `SESSION_SECRET` and `CSRF_SECRET` are generated fresh on every run in the config (for example `crypto.randomBytes`). No fixed secret values are committed; they live only for the test run.
  - `PUBLIC_ORIGIN` is the Vite test origin. The OIDC settings point at the fake OIDC provider, started as a second `webServer`.
  - Restore the real liveness check (`GET /api/v1/health/live` returns 200) in `tests/e2e/smoke.spec.ts`; the stubbed signed-out redirect check stays.
- Server startup rule: in production the server refuses known test values for the secrets (`SESSION_SECRET`, `CSRF_SECRET`, OIDC client secret), so the test setup cannot leak into a real deployment. Implement it in the platform config validation with a unit test; this is the only server change in this card.
  - **Define "known test values" first, as one exported list in the platform config module** (not scattered string checks), and write the definition into this card's decision log before coding. It must cover at least: the fake OIDC provider's client secret and any other fixed value the E2E setup or test config uses, and any placeholder or example value committed in the repo (for example in an `.env.example` or compose file, if present). Because E2E generates `SESSION_SECRET` and `CSRF_SECRET` randomly per run, a list of exact values cannot catch those; add a minimum-length (and not-all-the-same-character) check for them in production as well, and say so in the definition.
  - Enforced only when `NODE_ENV=production` (or the config's existing production switch; check `platform/config.ts`). Outside production the E2E and test setups must still start.
  - Error text names the offending variable, never its value (hard rule 9).
  - Unit tests (table-driven, name with the relevant rule): each listed test value is refused in production, accepted outside production, and a normal random secret of valid length is accepted in production.
- AC-10 run with AI disabled; run the suite in CI against Compose.

Every stub response and request body is validated with the contracts Zod schemas, so the stub can't drift from the contract. A16 owns swapping in the real sign-in helper and rerunning the key flows, including the `409` conflict (see "Do"). The A12 axe checks (light and dark, 390 px) already cover the recipe screens. Keep them when the stubs go.

- 2026-11-16 (A15, decided by the project owner): A15 shipped `ac-08-shopping-sync.spec.ts` UI-only (fake API plus `EventSource` stub; responses and bodies are validated with the contracts schemas). **Acceptance criterion for A16:** the stubbed API and `EventSource` in the A12 and A15 specs are replaced by the real sign-in path against the real server, and AC-08 is rerun green, including reconnection. Per the A03 E2E decision, the fake OIDC provider carries this in CI; real Authelia stays the pre-release gate.

- 2026-11-17 (A15 follow-up, decided by the project owner): `smoke.spec.ts` failed because it expected a running API server. It is now UI-only like the other specs (stubbed `/api/**`, session endpoint returns 401, asserts the redirect to `/signin` and its heading) and needs only Vite. The proper fix is the "Start the real stack" item under "Do", including the startup rule that refuses test secrets in production. The startup rule stays in A16 rather than becoming its own card.

- 2026-11-17 (A16, definition of "known test values", recorded before coding): one exported list `KNOWN_TEST_SECRET_VALUES` in `apps/server/src/platform/config.ts`, matched exactly after trimming and case-folding, checked only when `NODE_ENV=production`, against `SESSION_SECRET`, `CSRF_SECRET` and `OIDC_CLIENT_SECRET`. Members: `test-client-secret` (the fake OIDC provider's client secret, `TEST_CLIENT_SECRET` in `auth/test-idp.ts`, reused by the E2E fake provider so there is one fixed E2E value), `client-secret-value` (config unit tests), `int-test-session-secret-0123456789` (auth integration tests), and generic placeholders `changeme`, `change-me`, `secret`, `password`. Placeholders in `.env.example` are added once the owner has pasted its secret lines (the file is not readable by the agent). Compose files under `infra/` hold no app secret values (they use `*_FILE` secrets). E2E generates `SESSION_SECRET` and `CSRF_SECRET` randomly per run, so an exact list cannot catch them; in production those two must also be at least 32 characters (already enforced everywhere) and not a single repeated character. Error text names the variable only.

- 2026-11-17 (A16 implementation notes): CI runs the suite against a PostgreSQL service container, not Compose, because AC-10 only requires working without AI access (no clean `docker compose up` requirement); the stack under test is started by `playwright.config.ts`. E2E uses its own ports (origin 5183, Vite 5184, API 3100) so it can run beside `pnpm dev`; `apps/web/vite.config.ts` reads an optional `MISE_API_ORIGIN` for this. A TCP forwarder in front of Vite (`tests/support/connection-proxy.ts`) drops the live-list streams for the AC-08 reconnect step, because Chromium's `setOffline` does not close an open stream and Vite's proxy hides an API-side cut. `pnpm e2e` resets the shared test database: do not run it together with `pnpm test:int` (use `MISE_TEST_DB_SUFFIX` for a separate lane).
